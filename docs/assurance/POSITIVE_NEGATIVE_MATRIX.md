# Positive and negative controls, per capability

Owner, 2026-11-06: "I see negative testing but no positive testing." This is the audit of every proof
under `tests/` and every hosted control in `.github/workflows/self-test.yml`: for each, the POSITIVE
control (the normal user's path works) and the NEGATIVE control(s) (what must be refused).
`tests/check_positive_negative_pairing.py` holds it current: a proof missing from this table, a negative
control with no positive control and no named reason, or a cited file that does not exist fails self-test.

"in-file" means the proof itself carries that case (most follow docs/PROOF_RULE.md: allowed, attack,
missing evidence, recovery). The phrase quoted is the proof's own description of the case.
